# 首版设计与实施计划（待确认）

状态：设计提案，尚未授权实现。两项实验已经结束；本轮完成本地证据核对，不启动执行者、监控、评审或后台服务。原始材料只保留在 Git 外；本文使用匿名实验 A（原生后台会话）、B（打印模式 runner），不包含私人路径、会话标识、供应商或业务资料。

## 1. 证据支持什么

证据等级：**源码核对**证明机制存在；**本地记录**证明历史记录中存在该事实，不等同于本轮重演；**隔离验证**证明合成环境中的行为；复盘文字不能单独升级为端到端保证。本轮未重跑业务测试、外部评审或真实通知。

| 观察 | 证据与差异 | 首版决定 |
| --- | --- | --- |
| 持久任务资产、原会话返修和独立验收可用 | 两组均有任务、候选和验收记录；A 两任务四类报告的登记摘要均与报告字节一致；B 交付摘要与验收绑定一致，有 27 项内容覆盖核对记录 | 保留 task/session/run/candidate 分层身份；交回结果不自动完成 |
| 脚本采样与事件推送可替代常态模型巡检 | 两组源码均有独立 watcher、本地摘要、queue 和显式 ack；A 保存 117 项已发送记录，但无法由此推算消费次数；B 探针绑定目标、nonce 和确认时间，约 31 分钟后确认 | 常态检查不调用模型；只对可处理事件唤醒；不承诺即时或恰好一次 |
| A 的监控不是可原样复制的可靠队列 | `update` 每任务只保留一个 pending，新快照会覆盖未 ack 事件；本轮合成调用已重现 approval→working 后旧 signal 消失。done 还会产生待验收通知 | 观察快照与待处理事件分开；保留所有未处理异常；空闲只记活动，不生成交付事件 |
| B 保留 deferred，但仍有降噪缺口 | 源码保存未处理旧事件；权限拒绝按工具 ID 区分，语义相同的新请求仍可能反复唤醒 | 保留 deferred 思路，增加同一阻塞周期的聚合；这是新增设计，尚未经实验验证 |
| 监控与开发恢复必须分开 | A 有原会话退出后 attach、PID 更新的任务记录及热加载修复提交；B 有同 session、新 run 的 runner 和结果记录。A 守护仅恢复 watcher；B 隔离测试实际恢复替身 watcher | 守护不重启开发进程；Leader 核对后才能接续原会话，并确认恢复后确实继续执行 |
| 权限授权与工具许可是两层 | A 记录原界面启用 auto，后因已授权外发仍被拒绝，降为 acceptEdits + 本 worktree 精确脚本规则；B 无审批界面，拒绝就是未执行，常可用原生读取或单独命令替代 | 不将 auto 作为通用预授权方案；不模拟按键批准；先用已许可替代入口，越界才请求用户 |
| 权限配置不是完整运行事实 | A 静态预检仅查部分配置，不能模拟权限引擎；权限历史字段仍写 auto，与后续降级记录不一致。B 最终 runner 参数可由源码还原，但不会追溯约束旧进程 | 每次运行记录实际版本、模式、策略摘要和生效时间；策略改变不伪称在途进程已生效 |
| 无输出、退出码和评审标签不足以验收 | B 历史结果含 exit=0 且 is_error=true，也有超时；两组均出现长评审、部分报告和无意义重复重评 | 检查最终结果、交付身份、候选内容、有效覆盖和真实测试；疑似停滞只诊断，不杀进程 |
| 收尾也有状态不一致 | A 两任务记录均已关闭，但监控快照一项仍未关闭，旧健康快照仍为健康；B 有 watcher、健康作业及 hook 清理记录 | 完成前对账任务记录、实时进程、后台服务和清理清单；历史健康文件不能证明当前健康 |

可复用的成功做法：范围化授权、隔离工作树、共享资源串行、失败带证据交回原会话、按内容绑定评审、独立验收及精确清理。应放弃高频模型巡检、working/done 即进展/完成、每次权限拒绝都向用户升级、无限全量评审、任意放行 Shell、重复 attach 不回收。

本轮重新运行 A 监控 31 + 守护 5 项、B runner 59 + 一次性交接 hook 3 项，全部通过。hook 能按 session/run/策略摘要隔离传递上下文，但首版打印模式采用退出后接续，不引入在途 hook。测试覆盖模拟通知与隔离进程，不证明真实网络故障、宿主重启、额度耗尽后自动推进或横幅可见性。没有可靠成本对照，不能声明节省比例。

## 2. 最小执行路径

**建议仅支持：本机 macOS GUI 登录态中的 Codex 协调会话 → Claude Code 打印模式 runner → 同 session 接续 → 执行者调用已配置的独立评审 → 协调验收 → 本地收尾。** 首版每个项目一个在途任务、一个执行者、一个独立 worktree；跨项目并发不在验收范围内。

选择 B 的原因是启动参数、同会话恢复、新 run 身份和交付门禁能从现存脚本核对；A 原生后台路径虽实际完成任务，但首发完整参数缺失，界面切权限依赖上下文。首版沿用 A 的权限边界与监控经验，不混用两条启动/审批协议。原生后台路径待补证据后另行评估。独立 worktree 在 A 有记录，但不能据此称 B 的 runner 与 worktree 组合已端到端验证；该组合必须在 D2/D4 演练。

| 层次 | 首版承担 | 复用与限制 |
| --- | --- | --- |
| Skill 指令 | 确定范围与权限、委派完整目标、诊断事件、原会话返修、评审意见处置、独立验收、恢复和收尾决策 | 判断由 Leader/执行者完成；脚本不会判断业务结果或授权真实性 |
| 确定性脚本 | 运行锁、记录身份、启动/结果收集、活动与心跳采样、事件持久化/去重/重试/ack、候选及证据摘要检查、清理核对 | Python 标准库 + Git；借鉴两组机制，不直接复制项目硬编码或未确认许可的源码 |
| Harness/宿主能力 | Claude 执行、会话恢复及工具权限；Codex queue 事件入口；Git worktree；macOS launchd、可选系统通知 | 用现有入口，不另建调度平台或监控 App；实际版本与能力必须在目标机器预检 |
| 项目配置 | 需求入口、允许范围、验证命令、资源锁、评审入口/停止条件、环境引用、授权与清理清单 | 不内置测试账号、供应商、模型或业务门禁；项目已有校验/评审优先直接调用 |

打印模式初始策略建议采用实验中使用的 `acceptEdits`、关闭交互审批、任务专属 allow/deny。实现前核对目标 CLI 的实际参数能力，不把实验版本当永久兼容性保证。限制 Shell 规则不等于 OS 沙箱：被允许的测试仍能执行项目代码。不得更改全局权限或忽略既有 deny。

范围外：多 Harness 适配、原生子 Agent 路径、并行 DAG、统一评审引擎、自动批准权限、自动重启开发者、跨机器与登出/重启续跑、通知服务 SLA、插件及安装分发。首版不引入第三方编排依赖；不因 README 列出候选项目就开展新的依赖集成。

## 3. 最小契约与推进闭环

复用项目现有任务文档作为需求入口，另设一个版本化的脱敏任务清单；机器运行态和日志放入项目忽略目录，不复制现有任务体系。初版字段建议如下，编码前固定 schema 与版本：

- **task**：task_id、范围/验收入口、repo/worktree/base、验证与评审入口、资源锁、权限依据引用、清理清单、下一步。
- **run**：task_id、session_id、run_id、实际 CLI 版本与策略摘要、启动时间、PID 与启动身份、日志/结果位置。接续保留 session，新建 run；旧运行证据不冒充当前交付。
- **event**：event_id、task/run、kind、reason、revision、时间、证据索引、负责人及下一步；pending、发送结果、处理回执分别记录。进程活动不进入业务完成状态。
- **delivery / acceptance / cleanup**：候选完整提交、验证与评审证据摘要、限制；独立验收绑定 delivery 字节摘要和候选；清理记录绑定验收与本任务资源身份。摘要约束一致性，不证明来源可信或行为真实。

业务主线：`prepared → running → review/repair → delivered → accepted → closed`。`blocked` 记录原因、负责人、等待对象、返回阶段；`execution_failed` 与 `monitor_fault` 分开；`suspected_stall` 是诊断信号，不是业务终态。返修生成新候选并回到必要验证/评审，不能继续沿用过期 PASS。

1. **派发**：Leader 核对工作区、范围和授权；冻结基线、创建/复用独立 worktree，做 CLI/权限/通知探针预检；锁内启动一次。禁止同时恢复同一 session。
2. **监控**：默认 60 秒采样；进程身份、子进程类别、产物更新、日志新鲜度和 watcher 心跳分开保存。每 15 分钟可提交系统本地通知；持续可查摘要包含观测时间、记录阶段是否过期、活动、阻塞、下一步和健康状态，不生成模型摘要或百分比。
3. **阻塞处理**：权限拒绝先由执行者使用已允许的等价命令；结构化记录 `permission_denied`，不能伪称有待点击的审批。确实无法继续时通知 Leader；Leader 复核既有授权、原始拒绝及副作用，范围内调整任务局部策略，必要时等旧运行退出后接续，绝不声称热更新已生效。缺少权限或业务授权才向用户提出具体操作、载荷、目的地和理由。
4. **评审返修**：执行者使用项目已配置的独立评审入口；先锁定候选，核对实际 completed、partial/failed 和内容绑定。首版只沿用完全相同内容的有效证据，变化部分连同影响重新评；不实现通用逐文件继承算法。同一问题两轮仍不收敛或同项连续两次工具失败，停下交 Leader 决策，不自动全量循环；无改动且首次完整通过不空跑复审。
5. **验收**：先提交代码/测试/文档候选；评审证据与引用候选的 delivery 写入运行目录，验收和清理也在该目录，避免文件引用自身提交的循环。运行目录在原机器持久保存至归档，不随 worktree 删除。项目需要归档时另提交脱敏摘要，不豁免任意候选后代码差异。Leader 核对真实 diff、干净工作树及未跟踪文件、结果身份、必要测试与覆盖、未解决阻塞和限制。测试命令在锁内执行，共享测试资源按配置串行；不因脚本校验通过代替独立判断。
6. **收尾**：验收后只执行已授权的本地集成；无集成授权则保留分支/worktree，明确登记保留原因，不宣称已合并。授权集成后检查目标分支和候选关系，补相关集成验证；集成结果不等价时重新验收。停止本任务服务、watcher、健康作业、客户端和临时规则；核对无遗漏后 closed。清理失败保留 accepted + cleanup_pending，不伪报完成。不 push、部署或重写历史。

## 4. 事件推送与恢复约束

- 事件生成与观察快照分离；每个未处理事件不可被后续普通进展覆盖。相同任务/run/原因/阻塞周期聚合，保留各请求摘要；新权限范围、新候选和新异常必须生成新 revision，不能被“相同 HEAD”吞掉。聚合与不丢事件需新增测试证明。
- 投递首次失败后 60 秒、再隔 300 秒重试，最多三次；超时记投递结果未知，允许重复到达。成功入队不自动 ack；消费方重读当前事件，执行或持久记录负责人/阻塞/下一步后按精确 revision 确认。ack 不是问题已解决，未解除阻塞仍可见。
- 每任务保存发送与消费回执、nonce、目标会话和时间；没有当前机器上的真实探针消费确认，不标记推送可用。可在有授权时使用临时低频模型兜底，或明确降为用户手动查看；不默认创建周期任务。
- 耗尽、长期未 ack、额度受限时保留事件并显示 degraded/待人工处理，写本地摘要，尝试可用的系统通知；这不是独立的必达通道。协调人恢复后先读 pending、回执与实际状态，核实未重复处理，再继续。所有支撑进程停了就不会自动推进。
- 默认无输出 60 分钟、评审/测试无可观察进展 30 分钟产生一次疑似停滞事件；这些是可配置诊断阈值，不能当完成期限。明确等待授权、锁或用户时单独记等待原因和复核时间，不误报运行失败；监控仍更新心跳。
- launchd 默认每 60 秒查 watcher，心跳超过 180 秒才检查恢复；滚动一小时最多三次，只操作身份匹配的 watcher。PID 复用、配置错误或恢复耗尽记录 monitor_fault，不发信号给无关进程。滚动限额为首版提案，不能混称两组守护均已验证此策略。
- 开发进程退出：先核对 runner/子进程、当前 run 结果及最终 result；未知退出码保持未知。Leader 确认无旧执行者、没有未决外部副作用后，以同 session 新 run 接续；恢复后核对新 PID、日志/动作和下一步。无法确认外部写入结果时先对账，不盲重试。

## 5. 实施计划（确认后执行）

| 阶段 | 产出与范围 | 退出条件 |
| --- | --- | --- |
| D0：本轮设计 | 证据核对、范围、契约、验收矩阵；本地补证据提示词 | 用户确认执行路径及范围；影响设计的缺证据已回答或明确保留为非支持项 |
| D1：固定契约 | schema、合成任务样例、CLI 能力预检、权限/评审/资源约定 | 身份、候选、目录边界和未处理事件的反例可拒绝；不含私人配置 |
| D2：单执行者闭环 | 最小 runner，锁、同 session 接续、结果校验及交付/验收门禁 | 合成项目完成一次派发→开发→独立评审→返修→交付→验收；旧 run/过期候选不能通过 |
| D3：监控与恢复 | watcher、持久事件、queue 回执、本地摘要、launchd 守护、精确清理 | 隔离故障场景全部通过；目标本机真实通知探针确认后才启用该路径 |
| D4：Skill 与真实试运行 | Leader/执行者指令、安装前置说明、一个非敏感真实任务 | 完成全链路验收及资源对账；无缺失评审或关键测试；记录人工介入和模型唤醒数，不预设节省指标 |

只迁移被需要的机制，不复制两组完整运行平台。若许可、CLI 能力或评审入口不满足前置条件，记录阻塞，不默默更换为未验证的执行路径。

## 6. 验收场景

以下均为未来实施的门禁，不是本轮已实现。先使用临时仓库、替身 CLI/队列和可控时钟做隔离验证，再在目标本机进行授权的最小真实演练。

| 场景 | 注入与期望 |
| --- | --- |
| 正常完成 | 独立评审提出一项真实缺陷，原 session 修复后验证/复审；Leader 验收绑定最终候选，完成授权收尾，无重复执行者或残留服务 |
| 权限阻塞 | 已授权普通操作被拒绝，可替代时自行继续；必要操作无入口时只通知一次阻塞周期；超出授权的外发必须停下。未授权不执行；新范围不得被旧 ack 吞掉 |
| 进程退出 | 覆盖非零、无结果、退出码未知、exit=0/is_error=true；均不得交付。确认进程全退出后，同 session 新 run 恢复，旧 run 结果拒绝；有外部副作用先对账 |
| 长时间无输出 | 进程存活、评审检查点更新/不更新、已知等待权限/资源分别注入；按阈值仅诊断，不杀进程、不自动派发；新活动解除疑似停滞，等待仍可见 |
| 协调会话恢复 | 消费方停止期间保留多个异常，watcher 继续落盘；恢复读取当前候选和 pending，重复消息幂等处理；已处理动作不重做，未处理事件不遗失。额度受限不承诺自动推进 |
| 通知失败与并发变化 | 模拟非零、超时结果未知、重试耗尽、发送中新增异常、旧 revision ack；最多三次，不误删新事件；发送成功与消费处理分别计数 |
| watcher 故障 | 真正启动隔离替身，杀死或冻结 watcher；外部守护有限恢复，耗尽可见；PID 不匹配绝不杀，开发者进程不受影响 |
| 候选/评审失效 | 交付后代码或未跟踪文件变化、报告被修改、partial、必要覆盖缺失，必须拒绝验收；相同内容的复用必须核验摘要与环境 |
| 共享资源与收尾 | 锁竞争串行；仅删除本任务拥有且已授权清理的资源，保留其他修改；健康快照陈旧、监控状态未闭合或清理失败不得 closed |
