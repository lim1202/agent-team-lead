# Agent Team Lead

[English](README.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md)

**一个 Leader，多个开发 Agent，持续推进直到交付得到验证。**

Agent Team Lead 拟提供跨 Harness 的团队管理 Skill 及配套运行工具。协调 Agent 负责规划、委派、跟进、恢复和验收；执行 Agent 负责实现、测试及评审问题修复。用户（项目负责人）确定方向、查看进度，并处理必须由自己决定的事项。

本项目重点解决跨工具协调：当协调 Agent 的额度有限、开发需要交给另一个 Agent 工具时，权限、会话、通知和恢复机制的差异容易中断推进。原生子智能体可以承担工具内并行开发；本项目从实践中提炼可复用流程与脚本，帮助快速组织不同工具完成任务。直接出发点是消除人工中继：用户不必把协调工具生成的提示词复制到执行工具，再把执行汇报搬回来；由 Leader 直接派发、取得结果并推进返修。

项目围绕可信交付、真实进度和使用额度可用性，减少用户的注意力与协调负担。约定成果、责任和边界，保留 Agent 自主判断，优先复用项目门禁与工具原生自动化。

## 项目状态

**已提供首个指令版 Skill 源码；尚无配套运行工具、已验证的跨工具适配器或插件。**

并行前端迁移和 Webhook 服务两个真实项目实验均已结束。证据核对用于[首版设计](docs/v0-design.md)与[Skill 制作记录](docs/implementation-plan.md)。指令版不构成端到端兼容性或可靠性保证。

## 试用指令版

源码入口为 [`skills/agent-team-lead`](skills/agent-team-lead/SKILL.md)。按宿主工具支持的 Skill 安装方式加载该目录，再提出跨工具开发协调任务；当前会话将担任 Leader，并在派发前提供开工简报。项目缺少任务记录时，可使用可选的[任务记录提纲](skills/agent-team-lead/assets/task-record.md)。

Skill 提供协作指令，不提供执行服务或通知通道。实际使用需要可操作的执行工具、适当权限、可访问的项目记录，以及通知能力或约定的手动接续入口。新 Skill 尚未完成真实跨工具闭环验证。

## 职责划分

| 角色 | 职责 |
| --- | --- |
| 用户／项目负责人 | 确定目标和约束、查看进度，决定超出委派权限的事项。 |
| 协调 Agent／Leader | 负责完整任务生命周期，选择执行方、管理依赖、解除阻塞、验收并安排收尾。 |
| 执行 Agent | 按范围实现、运行检查、完成配置的独立评审与修复闭环，留下证据和交接记录。 |
| 确定性运行工具 | 跟踪进程与事件、校验记录、通知去重、健康检查，执行已授权的生命周期操作。 |

Leader 持续对推进负责。执行方返回结果是交接，不是自动验收通过。

## 设计原则

1. **持续负责直到完成。** 委派完整目标，无需用户反复催促，推进到验证和清理；Leader 负责协调与判断，不逐条遥控命令。
2. **判断与机械操作分离。** 脚本负责例行检查和状态转换，模型负责规划、诊断、评审和决策。正常监控不应反复调用模型。
3. **项目状态持久化。** 范围、决定、执行标识、候选版本、证据、阻塞及下一步跟项目走。会话用于追溯，不作为唯一恢复方式。
4. **进度可见。** 优先使用工具原生状态与日志，展示实际活动和最近更新时间；不虚构完成百分比，不把进程活跃当作业务进展。设计不要求另装监控 App。
5. **谨慎恢复。** 无输出只代表疑似停滞；检测进程退出及监控故障，保留现场，有限重试通知，并在安全时恢复原任务。不盲目重新派发有副作用的工作。
6. **在委派权限内行动。** 根据宿主能力预授权任务所需操作，真实例外才请求决策。不假设一个 Harness 的授权自动适用于另一个，也不默认放开整个 Shell。
7. **独立验收。** 交付与评审证据绑定任务、运行及候选版本；核对实际改动与相关结果，不能仅凭退出码、执行方报告或评审标签认定完成。
8. **有选择地并行。** 隔离工作树和任务产物；必要时串行使用共享账号、可变测试资源及集成操作。验收成为瓶颈时限制并发。
9. **减少用户参与例行调度。** 只汇报重要阶段、可处理的阻塞和最终结果；原生界面或确定性通知提供轻量进展，不为每次更新生成模型总结。
10. **核心与工具解耦。** 协调方和执行方不绑定产品；优先可靠的原生生命周期能力，缺失时使用明确的脚本替代并记录限制。

## 预期架构

下表描述职责划分与长期方向。首版只验证一条执行路径，并补齐该路径所需的必要机制。

| 层次 | 预期内容 |
| --- | --- |
| 通用 Skill | Leader 工作方式、委派约定、恢复判断、验收和汇报规则。 |
| 共享运行工具 | 进程与事件处理、健康检查、交付校验、通知有限重试及清理。 |
| Harness 适配层 | 通过各工具支持的接口启动、恢复、检查、发送指令、中断和发现能力。 |
| 项目配置 | 需求入口、验证命令、评审集成、环境引用、权限边界和共享资源规则。 |

Claude Code、Codex、Antigravity、OpenCode 和 DeepSeek Harness 是候选集成，并非已实现的适配器；Codex 原生子智能体也是候选执行方式。两种角色均不绑定供应商。

设计不承诺工具能力完全一致、无限无人值守运行，或在所有支撑进程停止后仍能推进。通知需要处理确认；协调会话无法接收通知时，需要明确的降级方式。

## 分发计划

计划由一个源码仓库提供可通过 `npx skills` 安装的 Agent Skills 包，并增加 Codex 和 Claude Code 插件包装。目前这些安装方式**均未实现**。运行依赖、宿主权限、后台服务配置及适配兼容范围将单独说明；安装 Skill 不会自动配置这些能力。
